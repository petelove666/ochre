# Theming

Ochre components are styled entirely with plain CSS and [CSS custom properties](https://developer.mozilla.org/en-US/docs/Web/CSS/--*) (design tokens).

Theme stylesheets are imported once, in a fixed order, in the app entry point ([src/main.jsx](../src/main.jsx)) and in Storybook's preview ([.storybook/preview.jsx](../.storybook/preview.jsx)):

```js
import './theme/brands/ochre/light.css'
import './theme/brands/ochre/dark.css'
import './theme/brands/alternative/light.css'
import './theme/brands/alternative/dark.css'
import './theme/tokens/light.css'
import './theme/tokens/dark.css'
import './theme/tokens/global.css'
import './styles/global.css'
```

Each file contributes a different layer, applied in this order:

1. **Brand** — `theme/<brand-name>/light.css`, `theme/<brand-name>/dark.css`
   Sets the brand specific colours e.g. accent colour
2. **Tokens (color scheme)** — `theme/tokens/light.css`, `theme/tokens/dark.css`
   Sets semantic color tokens for light/dark mode.
3. **Tokens (global)** — `theme/tokens/global.css`
   Sets tokens that don't change with brand or light/dark scheme (e.g. border radius), and applies brand tokens to global tokens eg. layers
4. **Base styles** — `styles/global.css`
   Applies styles to base HTML elements (`body`, box-sizing reset).

Component stylesheets (e.g. [OcButton.css](../src/components/button/OcButton.css)) never hard-code colors — they only reference `var(--oc-*)` tokens, so swapping a theme file changes every component automatically.

## Brand themes

A brand theme sets tokens, eg. `--oc-brand-accent-color` which are then used in the respective light/dark schemes, so the brand color flows through to any component that references those tokens (buttons, toggles, etc.).

Both brands' CSS files are imported at the same time; a `data-oc-brand` attribute on `<html>` selects which one is active — see "Switching brands with data-oc-brand" below.

```css
/* theme/brands/ochre/light.css */
@media (prefers-color-scheme: light) {
    :root[data-oc-brand='ochre']:not([data-oc-theme]) {
        --oc-brand-accent-color: rgb(210 165 60);
        --oc-brand-accent-color-text: rgb(0 0 0);
    }
}

:root[data-oc-theme='light'][data-oc-brand='ochre'] {
    --oc-brand-accent-color: rgb(210 165 60);
    --oc-brand-accent-color-text: rgb(0 0 0);
}
```

Two brands currently ship with Ochre:

- **ochre** — gold/ochre accent (`rgb(210 165 60)` light / `rgb(156 132 77)` dark)
- **alternative** — pink/magenta accent (`rgb(210 56 118)` light / `rgb(146 72 101)` dark)

Both brands only apply when `data-oc-brand` is set to their matching value (`'ochre'`/`'alternative'`); if the attribute is absent, no brand accent is applied and components fall back to their neutral `var(--oc-*, ...)` default colors.

### Adding a new brand

1. Create a new folder under `src/theme/brands/`, e.g. `src/theme/brands/my-brand/`.
2. Add a `light.css` and `dark.css`, each wrapped in the matching `prefers-color-scheme` media query and scoped with `[data-oc-brand='my-brand']` (and its `:not([data-oc-theme])`/`[data-oc-theme=...]` variants), setting the relevant tokens — see `theme/brands/ochre/*` for the pattern.
3. Import both files wherever the theme stack is assembled (`src/main.jsx`, `.storybook/preview.jsx`).
4. Add `my-brand` as an option to the `brand` toolbar entry in [.storybook/preview.jsx](../.storybook/preview.jsx).

## Light / dark mode

Light and dark tokens are defined using the `prefers-color-scheme` media query, so by default the theme follows the user's OS/browser setting — no toggle required.

```css
/* theme/tokens/dark.css */
@media (prefers-color-scheme: dark) {
    :root:not([data-oc-theme]) {
        --oc-body-bg: rgb(0 0 0);

        --oc-text-color: rgb(255 255 255);
        --oc-text-color-inverted: rgb(0 0 0);

        --oc-border-color: rgb(90 90 90);

        --oc-disabled-bg: rgb(65 65 65);
        --oc-disabled-text: rgb(190 190 190);

        --oc-primary-color: var(--oc-brand-accent-color, rgb(200 200 200));
        --oc-primary-color-text: var(--oc-brand-accent-color-text, rgb(0 0 0));
    }
}

:root[data-oc-theme='dark'] {
    --oc-body-bg: rgb(0 0 0);

    --oc-text-color: rgb(255 255 255);
    --oc-text-color-inverted: rgb(0 0 0);

    --oc-border-color: rgb(90 90 90);

    --oc-disabled-bg: rgb(65 65 65);
    --oc-disabled-text: rgb(190 190 190);

    --oc-primary-color: var(--oc-brand-accent-color, rgb(200 200 200));
    --oc-primary-color-text: var(--oc-brand-accent-color-text, rgb(0 0 0));
}
```

Both `theme/tokens/light.css` and `theme/tokens/dark.css` are imported at the same time; whichever media query matches the current color scheme wins, unless it's explicitly overridden (see below).

### Forcing a theme with `data-oc-theme`

Every token file also defines a `:root[data-oc-theme="light"]` / `:root[data-oc-theme="dark"]` block that mirrors its media query block, and the media query block itself is scoped with `:not([data-oc-theme])`. This means setting a `data-oc-theme="light"` or `data-oc-theme="dark"` attribute on the `<html>` element forces that theme regardless of the OS setting; removing the attribute falls back to `prefers-color-scheme` again.

Storybook uses this to provide a **Theme** toolbar control (System / Light / Dark) in [.storybook/preview.jsx](../.storybook/preview.jsx):

```jsx
const withTheme = (Story, context) => {
  const theme = context.globals.theme || 'system';

  useEffect(() => {
    if (theme === 'system') {
      document.documentElement.removeAttribute('data-oc-theme');
    } else {
      document.documentElement.setAttribute('data-oc-theme', theme);
    }
  }, [theme]);

  return <Story />;
};
```

The same `data-oc-theme` attribute can be used outside Storybook (e.g. in the app) to let a user override their system preference.

### Switching brands with `data-oc-brand`

Unlike light/dark mode, brand has no OS-level signal to default to — instead, setting `data-oc-brand="ochre"` or `data-oc-brand="alternative"` on `<html>` switches to that brand. Both brands' CSS files are always loaded; the attribute just selects which set of rules wins. Removing the attribute (or setting any other value) applies no brand, falling back to each token's neutral default color.

Storybook exposes this as a **Brand** toolbar control (Ochre / Alternative / No brand) in [.storybook/preview.jsx](../.storybook/preview.jsx), using the same `withTheme` decorator that drives the Theme control:

```jsx
useEffect(() => {
  if (brand === 'nobrand') {
    document.documentElement.removeAttribute('data-oc-brand');
  } else {
    document.documentElement.setAttribute('data-oc-brand', brand);
  }
}, [brand]);
```

The same `data-oc-brand` attribute can be used outside Storybook (e.g. in the app) to let a user pick a brand at runtime.

## Design tokens reference

- **`--oc-brand-accent-color`** — defined in `theme/brand{n}/light.css`, `theme/brand{n}/dark.css`
  Brand accent color for the active color scheme.
- **`--oc-brand-accent-color-text`** — defined in `theme/brand{n}/light.css`, `theme/brand{n}/dark.css`
  Text color for use on top of `--oc-brand-accent-color`.
- **`--oc-primary-color`** — defined in `theme/tokens/light.css`, `theme/tokens/dark.css`
  Primary interactive color, derived from `--oc-brand-accent-color` (e.g. `OcButton`, `OcToggle`).
- **`--oc-primary-color-text`** — defined in `theme/tokens/light.css`, `theme/tokens/dark.css`
  Text color for use on top of `--oc-primary-color`.
- **`--oc-body-bg`** — defined in `theme/tokens/light.css`, `theme/tokens/dark.css`
  Page/body background color.
- **`--oc-layer-bg`** — defined in `theme/tokens/global.css`
  Background for elevated surfaces (e.g. `OcCard`).
- **`--oc-layer-secondary-bg`** — defined in `theme/tokens/global.css`
  Background for secondary/nested surfaces (e.g. unselected `OcToggle` options).
- **`--oc-layer-secondary-bg-hover`** — defined in `theme/tokens/global.css`
  Hover background for secondary/nested surfaces (e.g. `OcTextInput`).
- **`--oc-text-color`** — defined in `theme/tokens/light.css`, `theme/tokens/dark.css`
  Default text/foreground color.
- **`--oc-text-color-inverted`** — defined in `theme/tokens/light.css`, `theme/tokens/dark.css`
  Text color used on top of dark areas (light mode) or light areas (dark mode)
- **`--oc-border-color`** — defined in `theme/tokens/light.css`, `theme/tokens/dark.css`
  Default border color for outlined surfaces.
- **`--oc-disabled-bg`** — defined in `theme/tokens/light.css`, `theme/tokens/dark.css`
  Background for disabled controls.
- **`--oc-disabled-text`** — defined in `theme/tokens/light.css`, `theme/tokens/dark.css`
  Text color for disabled controls.
- **`--oc-border-radius`** — defined in `theme/tokens/global.css`
  Shared corner radius used across components.

## Using tokens in components

Component styles should always read tokens through `var()` with a hard-coded fallback, so components remain usable even if the theme layer hasn't loaded:

```css
.oc-card {
    background-color: var(--oc-layer-bg, rgb(200 200 200));
    border: 1px solid var(--oc-border-color, rgb(130 130 130));
    border-radius: var(--oc-border-radius, 0.5rem);
    padding: 1rem;
}
```

When adding a new component, prefer reusing existing tokens above over introducing new ones. If a new token is genuinely needed, add it to `theme/tokens/global.css` (scheme-independent) or both `theme/tokens/light.css` and `theme/tokens/dark.css` (scheme-dependent), following the existing naming convention (`--oc-<purpose>`).
